# AI Instructions & Rules of Engagement

Цей файл містить обов'язкові правила для будь-якого ШІ-агента або асистента, який працює з кодовою базою проєкту **DefendWatch Med**.

---

## 1. Загальні принципи взаємодії
1. **Explain the Plan First:** Перед внесенням будь-яких змін у код завжди надавати чіткий покроковий план і пояснювати мотивацію змін.
2. **List Affected Files:** Обов'язково перераховувати повні шляхи до всіх файлів, які будуть створені, відредаговані або видалені.
3. **No Unrelated Refactoring:** Суворо забороняється робити «побічний рефакторинг», змінювати форматування сусідніх методів чи файлів, якщо це не стосується поточного завдання.
4. **Preserve Documentation & Comments:** Зберігати всі наявні коментарі, документаційні блоки та архітектурні угоди.

---

## 2. Робота з API та сумісність
1. **API Contract Integrity:** Не змінювати існуючі ендпоінти (`GET /`, `GET /health`, `POST /api/ai-guide`) та структури запитів/відповідей (`MedicalRequest`, `MedicalResponse`) без попереднього узгодження з користувачем.
2. **Documentation Sync:** Якщо змінюється або додається ендпоінт, модель чи поведінка — **обов'язково та синхронно** оновлювати відповідні файли в папці `docs/` (`api-contract.md`, `architecture.md`, `requirements.md`).
3. **Graceful Error Handling:** Завжди забезпечувати коректні HTTP-статуси (400 для помилок валідації, 500 для винятків бекенду) зі зрозумілим полем `detail`.

---

## 3. Безпека (Security First)
1. **No Hardcoded Secrets:** Ніколи не записувати API-ключі, паролі чи токени прямо у вихідний код.
2. **Protect `.env`:** Переконуватися, що файли `.env` та персональні конфігурації внесені до `.gitignore` і ніколи не потрапляють у Git.
3. **Medical Safety:** Забороняється змінювати системний промпт у спосіб, що дозволяє ШІ ставити клінічні діагнози або призначати ліки.

---

## 4. Тестування та перевірка якості
1. **Add Tests for New Features:** Кожна нова функція повинна супроводжуватися відповідними юніт-тестами (для FastAPI або Android).
2. **One Step at a Time (Controlled Vibe Coding):** Реалізація завдань має відбуватися атомарними мінімальними кроками з можливістю для користувача перевірити `git diff` перед фіксацією коміту.
