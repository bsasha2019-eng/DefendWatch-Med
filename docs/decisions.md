# Architecture Decision Records (ADR): DefendWatch Med

## ADR-001: Використання тунелю ADB Reverse замість відкриття портів брандмауера Windows

- **Статус:** Прийнято
- **Контекст:** Емулятор Android працює у власній віртуальній підмережі (`10.0.2.16`) і звертається до хоста через `10.0.2.2`. Брандмауер Windows Defender блокує вхідні пакети з віртуальної мережі на порт 8000, спричиняючи `SocketTimeoutException`.
- **Рішення:** Використовувати команду `adb reverse tcp:8000 tcp:8000` і адресу `http://127.0.0.1:8000/` на стороні клієнта.
- **Наслідки:** 
  - Позитивні: трафік іде через внутрішній ADB-міст на loopback-інтерфейс, не вимагає прав адміністратора, захищений від сканування в публічних Wi-Fi мережах.
  - Негативні: команду необхідно повторювати після перезапуску емулятора.

## ADR-002: Використання REST-транспорту для Google Gemini SDK на Windows

- **Статус:** Прийнято
- **Контекст:** За замовчуванням `google.generativeai` використовує транспорт `grpc`. На платформі Windows взаємодія з серверами Google через gRPC часто нескінченно підвисала на фазі рукостискання, викликаючи таймаути клієнта.
- **Рішення:** Вказати явний параметр `genai.configure(api_key=API_KEY, transport="rest")`.
- **Наслідки:** Запити відправляються через стандартний HTTPS REST, час відповіді скоротився до стабільних 1–2 секунд.

## ADR-003: Каскадний вибір моделей замість прямого виклику Reasoning-моделей

- **Статус:** Прийнято
- **Контекст:** Модель `gemini-3.8-flash` використовує важкий блок генерації "thinking tokens" (до 30–40 секунд), що неприпустимо для екстреної домедичної допомоги. Попередні моделі (`gemini-2.5-flash`) були оголошені застарілими для нових акаунтів.
- **Рішення:** Сформувати список пріоритетів швидких Flash-моделей (`gemini-flash-latest`, `gemini-2.5-flash-lite`, `gemini-3.5-flash-lite`, `gemini-3.8-flash`) з індивідуальним таймаутом 10 секунд на рівні `request_options`.
- **Наслідки:** Забезпечується максимальна швидкість відповіді без ризику падіння бекенду при недоступності окремої версії моделі.

## ADR-004: Вибір Jetpack Compose для інтерфейсу Android

- **Статус:** Прийнято
- **Контекст:** Необхідність швидкої розробки сучасного, реактивного та легко тестованого UI без зайвого бойлерплейту XML-розмітки.
- **Рішення:** Реалізувати весь інтерфейс за допомогою Jetpack Compose та Material3.
- **Наслідки:** Проста інтеграція корутин (`rememberCoroutineScope`), чистий декларативний код керування станами завантаження та помилок.

## ADR-005: Розширення таймаутів OkHttpClient до 60 секунд

- **Статус:** Прийнято
- **Контекст:** Стандартний таймаут Retrofit (10 секунд) призводив до помилок `SocketTimeoutException`, якщо LLM-моделі на бекенді потребували трохи більше часу на холодний старт або обробку.
- **Рішення:** Явно сконфігурувати `connectTimeout(60, SECONDS)` та `readTimeout(60, SECONDS)` в `OkHttpClient`.
- **Наслідки:** Висока стійкість клієнта до коливань швидкості генерації ШІ.
